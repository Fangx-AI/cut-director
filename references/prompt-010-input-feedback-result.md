# Prompt 010: 输入—反馈—结果三拍因果链

这个 Prompt 用“输入 → 即时反馈 → 结果”三拍结构解释一个动作怎样得到结果。所有文案与样式可编辑，结果图可选；演示文案只是示例，不属于模板的固定内容。

> **类型：可编辑 Motion Graphic 因果讲解。** 它默认是后期抽象解释，不应伪装成某个真实产品的原生界面；如要演示真实产品操作，应以来源可验证的录屏或截图为底层证据。

[观看已验证演示视频](../assets/verified-prompts/prompt-010-input-feedback-result.mp4)

## 用户直接使用的通用 Prompt

```text
在 [目标时间段] 制作一段“输入 → 反馈 → 结果”三拍因果讲解镜头。独立演示默认使用 1920×1080、30fps、3.5 秒。使用以下可编辑内容：[场景标签]、[第 1 步标签]、[输入眉题]、[输入文字]、[第 2 步标签]、[反馈短句]、[第 3 步标签]、[结果眉题]、[结果标题]、[结果说明]、[结果元信息]，以及可选的 [真实结果图片]。同时开放背景色、卡片色、主文字色、辅助文字色、主强调色、次强调色和字体。

所有文案必须保留为 Motion Graphic 可编辑文字属性，不得烘焙进 PNG、截图或视频。未填写的可选字段直接隐藏并自动回流；没有结果图片时使用完整的单栏结果卡，有来源可验证的真实结果图片时才切换为图文双栏，图片使用 contain 完整显示，禁止生成、重绘或虚构产品 UI，也禁止保留空白图片区、骨架线、占位词或假数据。

动画节奏固定为：第 5–28 帧逐字输入 [输入文字]；第 28–48 帧把输入卡压缩并过渡为反馈胶囊；第 35–58 帧显示 [反馈短句]；第 52–74 帧让结果卡进入；第 74–88 帧完成结果卡落稳；底部因果进度线从第 0–96 帧连续推进，最后保持到第 104 帧。三个阶段必须能清楚读成“动作发生—系统反馈—结果出现”，不添加无关粒子、故障、连续 whoosh、突然闪黑或末尾硬切。

本镜头默认是编辑层的抽象因果说明，不得把输入框、反馈和结果卡冒充某个网站的原生界面。如果任务是在证明真实产品操作，先使用用户提供或项目中已验证的真实录屏/截图作为底层证据，再把本 Prompt 的标签作为明确的后期讲解层；无法取得真实素材时，只能保留抽象讲解，不声称它是产品实录。

先展示输入开始、输入完成、反馈胶囊、结果卡进入、结果落稳和最终保持帧；核对全部文字可编辑、可选字段正确回流、真实结果图来源可靠、三拍因果清楚且结尾稳定后再导出。
```

## 用户需要替换什么

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 输入文字 | 是 | 第 5–28 帧逐字出现 |
| 反馈短句 | 是 | 简短、直接，说明动作已被接收 |
| 结果标题 | 是 | 给出最终结果，不写假数据 |
| 结果说明 / 元信息 / 眉题 / 步骤标签 | 否 | 留空后隐藏并回流 |
| 真实结果图片 | 否 | 仅使用用户提供或项目已验证素材，contain 显示 |
| 色彩与字体 | 否 | 可替换，但三个阶段层级必须清楚 |

## 两种合法使用方式

1. **抽象因果讲解**：只使用 Motion Graphic，明确属于后期解释，不声称是产品实录。
2. **真实操作标注**：以可验证录屏或截图为底层证据，本 Prompt 只承担输入、反馈和结果关系的编辑标注。

## 固定的动画骨架

- 画布：1920×1080，30fps，105 帧。
- 输入：第 5–28 帧。
- 形变与反馈：第 28–58 帧。
- 结果：第 52–88 帧进入并落稳。
- 因果进度线：第 0–96 帧。
- 收尾：第 88–104 帧稳定保持。

## 验证清单

- 输入、反馈、结果三拍都能单独读懂，前后因果明确。
- 所有文字、标签、颜色与可选图片均可编辑。
- 可选字段为空时自动回流，无空白卡槽或占位内容。
- 真实产品模式使用可验证底层素材；抽象模式不冒充产品原生 UI。
- 第 0、28、48、58、74、104 帧以及实时播放均无闪黑或突然退场。
