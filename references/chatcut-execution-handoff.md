# ChatCut 口播剪辑执行 Handoff

## 进入条件

按本次任务读取当前宿主能力和授权。用户要求语音清理，允许执行范围内可恢复的语音剪辑；要求只预览，则不应用。字幕、声音、动画和导出分别遵循用户请求，普通语音清理不等待 Visual Beat Map。

视觉 Recipe 写入前，按 `references/pipeline-contract.md` 初始化或恢复 manifest，合并当前事实并运行写前 transition。状态实际进入 `executing` 后才执行对应写入。语音剪辑使用当前 Script、源区间和粗剪版本记录，不为它创建无关动画 Recipe。

## 视觉代表片段

新增视觉方向需要让用户看到具体方案；先完成一个代表性 Beat 再验证扩展。方案说明实际文字、人物处理与费用，已有确认与明确请求在其范围内继续有效。这个流程针对视觉制作，不能阻断已请求的去口癖、重录清理或字幕修订。

用真实授权记录视觉 manifest 的 first / second evidence；执行后检查结果再展示。用户未授权扩展时等待确认；已明确授权的范围不要重复索取同一决定。不得把工具成功、方案或静帧描述为已完成的声音与画面验收。

## 当前宿主与授权延续

先读 [兼容说明](compatibility.md)，区分内置 Agent、Desktop ACP / local CLI 和 hosted 插件。Desktop 直接 JSX 不等于内置生成路径；本地 Remotion TSX 不能直接当作 ChatCut MG 输入。

执行端必须与用户这次选择一致。Desktop 工具存在不意味着可用它探测或修改无关仓库任务；Codex Browser 中的网页也不是 Desktop。确认目标项目和实际可播放媒体，注意桌面本地素材不会自动出现在网页。只在真实权限和工具合同允许的表面继续。

先恢复同一来源中仍有效的用户确认，不因换一轮对话重新索取同一授权。局部修改可沿用已接受的方向和对应范围，更新受影响事实与写后证据；新增范围或方向则取得对应确认。manifest 的 first / second evidence 仍必须来自实际用户授权，不能为通过门禁填造。

## 执行 Skill 路由

先发现当前实际可用的 Skill 与工具；下表是能力名称，不保证每个宿主使用相同命名。没有同名 Skill 时根据真实工具描述执行，不编造能力。

| 任务 | Skill |
| --- | --- |
| 读取/处理口播剪辑原则 | `chatcut:talking-head-guide` |
| 获取 transcript、字幕和词点 | `chatcut:transcription` |
| 去口癖、重录、冗余与停顿 | 当前 Script 能力：读取、局部编辑、预览/应用与写后回读；见下节 |
| 创建或放置 MG | `chatcut:create-motion-graphics` |
| 生成视频补画面 | `chatcut:video-gen` |
| 生成或编辑静态画面 | 当前宿主实际提供的图片能力；不假设 Codex 包存在 `chatcut:image-gen` |
| 导入用户或外部素材 | `chatcut:asset-import` |
| 背景音乐和节奏 | `chatcut:music` |
| 音效或旁白 | `chatcut:voice` |
| 检查时间线和画面 | `chatcut:verification` |
| 导出成片 | `chatcut:export` |

如果某个 Skill 不可用，报告缺失能力，不编造工具调用或执行结果。

## 语音剪辑执行

1. 读 [语音剪辑规则](speech-editing.md) 和当前官方 talking-head / transcription 指南，定位可读源媒体。
2. 读取当前 Script。核对重复尝试、上下文、可用词点与音频；修 ASR 和删原声分开处理。首次写入前保存 Script、源媒体身份与源区间，使用可恢复副本或版本；原媒体不覆盖，私有缓存不公开。
3. 固定犹豫词和空等可使用当前批处理工具；中文字符与有语义的连接词不能按词表删除。工具会立即写入时，不用于 preview-only 请求。
4. 对语义编辑使用最新 Script，删除确实失败、被覆盖或无意义的部分。宿主支持 preview 时先验证；应用已经授权则成功后直接应用。
5. 每个真实写入批次后回读 Script 与时间线；部分失败时以实际状态继续，不重放整批。
6. 试听改变的接缝，检查完整意思、重复遗漏、气口、人声与人物同步；反馈只修相关段落。
7. 保存当前粗剪身份、实际删句及源区间。恢复一句时局部恢复原声，不只补字幕或全局撤销；回读并重锚受影响内容。线性 1x 时可使用 [剪辑计划工具](speech-edit-plan.md) 检查词点与重锚时间；它不代替宿主写入或试听。
8. 展示可用粗剪、时长与少量重要改动。继续做字幕和动画时以当前粗剪 transcript 为准。

不要用 `manage_transcript` 改字假装剪掉原声，不用 `find_transcript` 代替 Script 组装。不要在主视频轨留意外 gap 制造气口。实际工具字段与 Script 标记语法以当前宿主为准。

## 字幕、声音和导出

按 [口播流程](talking-head-workflow.md) 的对应环节执行。字幕从当前粗剪生成，声音处理后试听人声与音乐关系，导出读取实际文件的分辨率、音视频与首尾。已有动画后来经历语音删改时，重新定位并检查；旧的 verified 时间不能直接延续。

## 代表性 Beat 执行顺序

1. 恢复同一来源的 manifest，合并最新项目事实，不覆盖已确认值。
2. 重新确认 Beat 的文案锚点、时间、画幅、人物处理和保护区。
3. 运行确定性验证并进入 `executing`，记录唯一 operation ID；失败则按阻断原因停止或降级。
4. 以当前已接受的 A-roll 时间为锚；正在做完整剪辑时先稳定语音清理，不用原片旧时间。
5. 检查 Beat 开始、中间和结束附近的真实画面。
6. 根据 Beat 类型创建一项 MG、生成画面或导入素材，只放置到批准的时间范围。
7. 检查字幕、脸、手势、产品、Logo、文字和运动路径。
8. 把实际素材、开始、中段、结束证据写回 manifest，再次验证并进入 `verified`。
9. 向用户展示代表性结果。尚未授权扩展时等待确认；已经存在相应授权时记录真实 evidence 并在该范围内继续。

## Handoff 包

执行者接收：

```markdown
- Beat ID 和文案锚点
- 精确或约时间范围
- 主视觉语言
- 官方结构参考
- 画面设计
- 人物处理与位置尺寸
- ChatCut 用户提示词
- 导演约束层
- 生成 prompt（如有）
- 保护区
- 可编辑字段
- 廉价风险
- Quality Gate 评分和结论
```

缺少人物处理、保护区、质量结论或可验证的 manifest 状态时，不执行该 Beat。

## 额度和确认

MG、视频和图片生成可能触发 ChatCut 确认卡或消耗额度。不要绕过确认；确认被拒绝、取消或超时时，停止并等待用户新指令。属性面板中的文字、颜色、字体、位置和时长调整优先用于低成本迭代。

## 失败降级

1. 先删除一个竞争动作或装饰。
2. 生成视频失败时尝试更明确的单镜头约束。
3. 第二次仍失败时改用生成图片、MG、真实 B-roll 或保持干净。
4. PiP 无安全区时改为分屏、全屏或原画面。
5. 任何降级都更新 Visual Beat Map，不默默改变导演意图。

## 扩展整条视频

复用已确认的字体、色板、形状和运动语法，不复制每个 Beat 的具体模板。每完成一组 Beat 后运行 ChatCut verification，检查整体密度和连续性；连续重视觉后恢复人物和留白。
