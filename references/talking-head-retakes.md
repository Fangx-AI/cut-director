# 重录与口误的判断

[返回口播纯剪辑指南](talking-head-cut.md)

去停顿和语气词靠规则就能做好，真正决定剪得好不好的，是能不能认出说话人"重说了"，删对范围，并留下最好的一遍。这份文档给出判断顺序、常见信号、取舍标准和实例。

总原则是**删前保后**：同一个意思说了几遍，删掉前面的，保留后面更完整的那一遍。只有后面那遍说错或没说完时才例外，例外要在交付说明里提一句。

## 判断顺序

对每一处可疑的地方，按顺序回答这五个问题：

1. **有没有重说信号？** 对照下面的信号表。没有信号就不动。
2. **废弃的是哪一段？** 找出被放弃的那一遍从哪里开始、到哪里结束。
3. **留哪一遍？** 有多遍时按"选哪一遍"的标准挑。
4. **拼起来通不通？** 把删除后的前后文连起来读一遍，必须是一句完整、通顺、意思没变的话。
5. **风险高不高？** 按"风险分级"处理：高风险项先做反向复核；没把握就保留，并在交付时提一句。

## 重说信号

| 信号 | 例子 | 通常怎么处理 |
| --- | --- | --- |
| 明确的重来口令 | "重来""再来一遍""等一下""不对不对""算了""卡了""这段剪掉" | 删掉被放弃的那一遍，连同口令本身 |
| 整句重启 | "今天我们来聊……／今天我们来聊一聊 AI 剪辑" | 删掉前面没说完的那遍 |
| 半句重复 | "我们可以，可以直接导出" | 只删重复的那几个字 |
| 句内"A＋插入＋A" | "这个功能，就是说，这个功能很好用" | 删掉前一个 A 和中间的插入语，从后一个 A 接着说 |
| 残句 | 话说一半停住，停顿后换了说法重新说 | 删掉整个残句 |
| 重说前的铺垫语 | "我重新说一下""换个说法""我的意思是""简单来说就是"出现在重说之前 | 和被放弃的那一遍一起删掉。正常讲解中的"简单来说"保留 |
| 改口 | "三月……不对，四月上线" | 删掉说错的部分和"不对"，保留改正后的说法 |
| 同一句录了多遍 | 隔几秒到几十秒，同一句话又完整说了一次 | 按"选哪一遍"挑一遍，其余删掉 |
| 无声信号 | 拍手、响指（波形上一个尖峰），或者一段长停顿后从句首重新开始 | 和重来口令一样处理，拍手声也要删掉 |
| 句间重复 | 相邻两句、或隔一句的两句开头相同，前一句没说完或说得更差 | 删掉前一句整句 |
| 交叉重录 | 第一遍说完，接着冒出半句别的，又把第一遍换个说法重说一次，再往下讲 | 两遍里留一遍，连同夹在中间的半句一起删（见例 9） |
| 边说边改主意 | 同一个位置说了好几遍，每遍意思都在变（"对社会有用"→"对大家有用"→"对用户有价值"） | 留和下文衔接最好的那一遍，交付时一定要提（见例 10） |
| 远距离更正 | 1:10 说"支持 10 种语言"，3:20 又说"刚才说错了，是 20 种" | 不替用户改内容，默认两处都留，交付时一定要提（见例 7） |

辅助判断：被放弃的那一遍往往没有句末语气，尾音上扬或戛然而止，后面跟一段比平时长的停顿，然后从句首或从某个词重新开始。

时间上，改口和半句重复通常发生在 3 秒以内；整句重录可能隔 5 到 60 秒，所以要往后看足够远，不要只比较相邻两句。

## 风险分级

不是每个删除项都要同样谨慎。先分级，把用户的注意力留给真正可能删错的地方：

| 级别 | 包括 | 处理 |
| --- | --- | --- |
| 低风险 | 缩短停顿；紧接着、逐字相同地重复 5 个字以内（哪怕在句子中间）；单独的"嗯、呃"和前后有停顿的单独口头禅；开头和结尾没说话的部分 | 直接删除，交付时不用逐条提 |
| 高风险 | 删除整句；在句子中间删掉不完全相同的内容；保留的不是最后一遍；长段重复；每遍意思不同；和前后文的意思有冲突；远距离更正；接缝落在人声上 | 先做一次反向复核；仍然要删的记进剪辑记录，最没把握的几处在交付时提 |

**反向复核**：对每个高风险项，换个立场问一遍"如果这段其实不该删，理由是什么"：

- 它是不是排比、强调或刻意的对比？
- 删掉以后，后文里的"它""这个""刚才说的"还有没有着落？
- 保留的那一遍是不是真的更好？

找到站得住的理由，就改为保留，或标为需要用户决定。

## 删到哪里

- **起点**：说话人重说时通常回到句首，所以从被放弃那一遍的句首删，而不是从说错的那个字删。只是半句重复（"可以，可以"）时，只删重复的部分。
- **终点**：删到重说那一遍开始之前，包括中间的停顿、"不对""重来"和拍手声。
- **下刀**：两端都要落在静音上，规则见[剪辑指南](talking-head-cut.md#怎么下刀)。
- **拼完重读**：所有删除项定下来以后，把剪后的全文从头读一遍，专门扫三类残留：
  - 剪辑点两侧出现重复的词，如"所以，所以""这个这个"
  - 相邻两句开头相同
  - 被删掉一半的口误
  
  同时检查指代是否清楚，"它"指的东西不能被删掉；语气要接得上，不能前一句扬调、后一句突然接新话题。
- **拖长音陷阱**："那——个""然后——"这样拖长的字，在转写里可能显示成一个短字加一段停顿。如果把这段"停顿"当静音剪掉，就会把字切成两半。拖长的字整个保留，或者整个删掉。
- **时间戳要复核**：重录多的素材，识别时间可能偏差一秒以上，尤其是长句的开头和结尾。高风险项下刀前，把边界前后几秒单独再听一遍，或者重新识别一次，确认无误再剪。
- **是口吃还是识别错了**：转写里出现叠字（"意味味着""画的画的"），可能是真的口吃，也可能是识别出错。用另一个识别（或同一个识别换个参数）核对这一小段：两次结果一致才删，不一致就不删。删完后重新识别成片，接缝附近文字变了，说明切坏了，撤回。

## 选哪一遍

按顺序比较，前一条分出高下就不再往下看：

1. **内容完整、没有说错**：说错数字、名字或事实的那遍直接淘汰。
2. **流畅**：没有卡顿、没有"嗯呃"、中间没有长停顿。
3. **语气和状态**：更自信、更有精神，和前后句的语调接得上。
4. **画面**：眼睛看镜头，没有低头看稿，表情自然。做法：每一遍取中间一帧，加上开头和结尾各一帧，放在一起比较。
5. **都差不多时，留最后一遍**：说话人通常越说越顺，最后一遍往往是他想要的那一遍。

## 不要删

这些看起来像重复，其实是有意的表达：

- 排比和递进："要快，要准，还要稳。"
- 强调的叠用："这一步非常非常关键""记住，记住"。
- 设问自答："为什么？因为……"
- 先引用再解释："他说'不好用'，不好用在哪？"
- 刻意的对比："不是 A，而是 B"。这是表达，不是改口。
- 固定的开场问候和结尾号召，即使每期都一样。
- 开头吸引观众的那句话（钩子）：清理时不能把它删掉或削弱。
- 识别错字：转写把"剪映"识别成"简影"，这是识别的问题，不是说话人的口误，不能据此删话。

## 实例

时间格式为分:秒。每个例子给出原文、判断和删除后的结果。

**例 1：整句重启**

```text
[00:31.2-00:33.0] 今天我们来聊一下
[00:33.9-00:37.5] 今天我们来聊一聊，怎么用 AI 剪口播。
```

判断：第二句开头和第一句相同，而且说得更完整，属于整句重启。删除 00:31.2–00:33.9（第一遍和中间的停顿）。

结果："今天我们来聊一聊，怎么用 AI 剪口播。"

**例 2：改口**

```text
[01:05.0-01:09.8] 这个功能是三月……不对，四月份上线的。
```

判断：改口。删除"三月……不对，"，从"是"之后下刀，接"四月份"。

结果："这个功能是四月份上线的。"

删除位置在句子中间，属于高风险项，下刀后要自己听一遍拼接是否自然。

**例 3：明确的重来口令**

```text
[01:40.2-01:42.1] 它的价格是……
[01:43.0-01:43.6] 哎，重来。
[01:45.1-01:48.0] 它的价格是每个月九十九块。
```

判断：有重来口令。删除 01:40.2–01:45.1，包括被放弃的半句、"哎，重来"和前后的停顿。

结果："它的价格是每个月九十九块。"

**例 4：同一句录了三遍**

```text
[02:10.0-02:14.5] 第一遍：剪完以后，嗯，你可以直接，直接导出到剪映。
[02:17.0-02:20.8] 第二遍：剪完以后，你可以直接导出到剪映。
[02:23.5-02:27.0] 第三遍：剪完以后，你可以直接导出到剪……导出到抖音。
```

判断：三遍说的是同一句。第一遍有"嗯"和卡顿；第三遍说错了平台，而且自己改口了。第二遍完整、流畅，所以保留第二遍，删除第一遍和第三遍。这里不按"默认留最后一遍"处理，因为最后一遍说错了。

结果："剪完以后，你可以直接导出到剪映。"

如果第三遍改口后的"导出到抖音"才是说话人想要的意思，就说明内容变了，必须问用户。

**例 5：半句重复**

```text
[02:40.0-02:43.2] 我们可以，可以直接把字幕导出来。
```

判断：半句重复。只删第一个"可以，"及其后的停顿。

结果："我们可以直接把字幕导出来。"

**例 6：看起来像重复，其实不能删**

```text
[03:01.0-03:04.5] 做口播要快，要准，还要稳。
[03:05.0-03:07.2] 这一步非常非常关键。
```

判断：第一句是排比，第二句是强调。都保留，不列入删除清单。

**例 7：远距离更正**

```text
[01:10.0-01:13.0] 它支持 10 种语言。
...
[03:20.0-03:24.0] 刚才说错了，它支持的是 20 种语言。
```

判断：后面的话在更正前面的事实，两处相隔两分钟。可以有三种处理：

- 删掉 3:20 的更正句，把 1:10 那句换成正确说法。但原片里没有正确说法可用，做不到。
- 删掉 1:10 那句和 3:20 的更正句，前提是删掉后上下文仍然通顺。
- 两处都保留。

这类情况代理不替用户改内容：默认两处都保留，交付时一定要提，写清楚两处的时间和原话，让用户决定要不要删。

**例 8：无声的重来信号**

```text
[04:00.2-04:02.0] 那我们看下一个……
[04:02.4]         （拍手声，波形上一个尖峰）
[04:04.0-04:07.1] 那我们来看下一个功能。
```

判断：拍手加上从句首重说，属于重来。删除 04:00.2–04:04.0，包括拍手声。

结果："那我们来看下一个功能。"

**例 9：交叉重录**

```text
[02:58.0-03:02.0] 当然你这个情怀可能本来就是错的，就是你做不出你梦想中的那个伟大的产品。
[03:02.3-03:05.0] 但是我们百分之九……
[03:05.0-03:10.0] 你可能做不出，你就是在脑海中想象的那一个伟大的或者说完美的一个产品。
[03:10.3-03:13.0] 但是我们百分之九十九的人……
```

判断：第一句后半和第三句说的是同一个意思，中间夹着一个没说完的"但是我们百分之九"。两遍留一遍，中间的残句一起删。

这种情况不机械套"删前保后"：后一遍更完整，前一遍更干脆，两种都通顺。默认留后一遍，交付时提一句"另一遍更短，想换就说"。

**例 10：边说边改主意**

```text
[01:27.7-01:31.0] 就是我刚开始做产品的时候，我想的是……
[01:31.5-01:35.5] 我想做什么东西，我做什么东西可能是对这个社会有用的……
[01:36.0-01:40.5] 我想的是，我做什么东西会对大家有用，我做什么东西会对……
[01:41.6-01:47.0] 就是我以前做产品想的是，我做什么东西可能会对我的用户有价值。
[01:47.3-01:50.0] 但是我现在只有一个想法，就是怎么让我的用户付费。
```

判断：说了四遍，但每遍的意思都不一样，是说话人在边说边想，不是同一句录了多遍。"选哪一遍"的第 1 条分不出高下，因为每遍都没说错。留和下文衔接最好的那一遍：第四遍的"对我的用户有价值"正好接上"怎么让我的用户付费"。

意思有变化，所以交付时一定要提："这段你说了好几遍，前面说的是'对社会有用'，我留了最后一遍'对用户有价值'，想换就说。"

## 写进剪辑记录

高风险项每一项都写清楚：

- 时间
- 被删的原话
- 删除后的结果
- 理由

有多遍时，说明为什么选这一遍。遍数多时压缩着写，不逐遍抄原话，例如"这句说了四遍，前三遍都没说完，留第四遍"。交付时提到它，也用同样的说法，例如：

> 2:10–2:27 这句录了三遍。我留了第二遍"剪完以后，你可以直接导出到剪映"：第一遍有卡顿，第三遍把平台说成了抖音。
