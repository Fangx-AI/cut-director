## 实际 GitHub 页面

检查的是 PR 分支在 GitHub 上的真实文件页面，不是自建预览站或 Markdown API 返回的 HTML。

- 中文首页、英文首页、效果画廊：分别检查 375、768、1440 像素宽度，浅色和深色，共 18 组布局。
- 三份页面的整页宽度均未超过对应视口；表格能在对应容器内呈现，没有隐藏末列操作。
- 封面、徽章和预览资源加载成功；减少动态效果模式下，画廊的 15 张 `currentSrc` 均切换到对应静帧。
- 正常动画模式下，画廊 15 张预览均加载，图片链接分别指向原 MP4；四条 WebP 文件逐帧解码有效，非空白静态文件。
- 手势案例在浏览器中的两个间隔截图存在实际像素变化；静帧模式与动画模式均检查过，而不是只改了 HTML。
- 观察首部、使用示例、案例交接、表格与收尾；实际点击中文首页“看真实效果”能定位标题，开发折叠区能展开。

页面截图和检查输出保存在本次工作目录的 `test-results/browser`，未作为 Skill 资产发布。GitHub 浮动文件工具栏可能遮住元素截图顶端，因此封面另以正常页面滚动位置检查。它不是封面裁切。

这些是当时浏览器的观察，不是独立无障碍审核，也不保证 GitHub 未来的 HTML 清理行为不变。

## 仍需完成的真实回归

新增语音分支还没有真人中文毛片的 ChatCut 端到端验证。发布为稳定语音剪辑能力前，至少需要：

1. 有权使用的未剪素材，覆盖犹豫音、完整重录、数字修正、有意义的连接词、刻意强调与章节停顿。
2. 记录拟删原句与源范围，应用后回读实际 Script，试听关键接缝，报告误删、漏删和恢复修改。
3. 检查剪后字幕、手势与动画的真实重锚结果、声画同步和黑帧。
4. 检查实际导出文件的音视频、分辨率与首尾，交付可播放前后结果。

本次没有操作用户现有的 ChatCut 生产项目，没有购买或消耗生成额度。PR 保持草稿；九条旧动画案例的验证标签不扩大为新增语音质量承诺。

可执行的私有素材步骤见 [完整验收方案](speech-acceptance.md)，包括只预览、自然粗剪、局部恢复、下游重锚与真实导出。该方案本身不计为已完成回归。
